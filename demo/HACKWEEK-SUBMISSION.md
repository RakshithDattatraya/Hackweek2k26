# Amplify — Feature → Enablement Pipeline (Hackweek Submission)

*Every ship, amplified to sales.*

## Elevator pitch
Engineering ships faster than sales can learn — so features land that nobody can articulate, position, or demo. The moment a feature is built, its context (the story, the persona, the pain it solves) is at its richest… and it's perishable. **Amplify captures that context at the source and auto-drafts a premium, on-brand enablement video and one-pager** — quality-checked, claim-verified, and routed to a human for approval before it publishes to YouTube, the enablement hub, and Slack. The engineer never becomes a marketer; their feature markets itself. (The demo video itself was generated end-to-end by the pipeline.)

## Project details
**The problem.** "Shipped" isn't "sellable." Builder-mindset engineers ship constantly; sales are baffled by the pace and can't tell what's new, what it's worth, or which customer it fits. Enablement fails because someone tries to reconstruct the feature's context weeks later, cold.

**The insight.** Context is perishable — and the builder already knows who they built it for. So enablement should be *shift-left*: a new step in the delivery pipeline, right after deploy, and a new item on the definition of done alongside unit tests, E2E, and docs — except this one fills itself.

**What it does.** From a pull request (diff + commits + description), it drafts a structured **VideoPlan**, generates bespoke on-brand scenes, reuses the engineer's demo recording with an eased **auto-zoom**, adds an expressive voiceover + ducked music + SFX + synced captions, runs QA gates, and emits **two artifacts from one plan**: a ~2-min video and a matching one-pager.

**Two directors (the core IP).** Most auto-demos feel off because they conflate two jobs. We split them: a **content director** (what the feature means + the sales layer, grounded in the diff — never invents a claim) and a **camera director** (where the eye goes / auto-zoom on footage).

**Trust model.** A **claim-check gate** compares every narration line against the diff; a made-up metric or integration is flagged and routed to a human. A **merge triggers capture, not publish** — a person approves before anything reaches a customer.

**Outcome.** Sales instantly knows what shipped, where it fits, how to position it, and the right-fit customer — and the engineer's work gets seen without extra work.

## Technology used
- **Runtime / language:** TypeScript on **Bun** (`bun test` for the suite), zod for schema validation.
- **Rendering:** **HyperFrames** (HeyGen's HTML→MP4 framework) — headless Chrome seeks a paused **GSAP** timeline frame-by-frame → **FFmpeg** → MP4. Deterministic, no build step.
- **Composition:** bespoke free-form scenes (HTML/CSS + authored GSAP), a design-token layer (UiPath brand colors/type), cross-scene seam transitions, kinetic captions.
- **Audio:** **ElevenLabs** expressive voiceover (swap-seam also supports macOS Ava/`say`), a mood-selected royalty-free **music library** ducked under the VO via FFmpeg sidechain, synthesized SFX, **Whisper** caption transcription.
- **Camera director:** FFmpeg scale-up + sub-pixel center-crop (jitter-free zoom/pan) with authored focus keyframes.
- **QA gates:** determinism lint, brand-palette check, HyperFrames render lint/validate, and an **agent-native claim-check** (skill reviews narration vs. the diff → `qa-report.json`).
- **One-pager:** branded HTML → PDF via headless Chrome.
- **Ingest:** git-based PR context (branch diff/commits); demo-clip detection.
- **The "brain":** an agent-native Claude **skill** (content director + claim-check). Deployable on the **UiPath Python coded-agents SDK** — agent orchestrates, invokes a render process, and uses **Action Center** for the human approval gate.
